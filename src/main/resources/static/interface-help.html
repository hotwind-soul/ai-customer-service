项目与业务资料

价格、标准话术、图片和支持门店尽量在项目中心集中维护。

业务权威来源
  1. 主项目显示在客户首页；子项目归入主项目，但可维护自己的报价、话术、图片和门店。
  2. 客户提到子项目名称或别名时，系统优先使用该子项目资料；父项目不会覆盖子项目的独立报价。
  3. 项目价格以项目中心为准。修改报价后无需再逐份修改 FAQ，知识库中的动态价格内容会按治理规则处理。
  4. 新建项目、图片和门店时先选择企业及客服号归属；已有资料的归属不会因顶部选择变化而自动修改。
  5. 门店先维护城市和区县，再关联到支持的项目；项目只会推荐已经关联的门店。
日常价格更新只改项目中心。知识库适合维护项目原理、流程和常见问题，不应作为活动价格的第二套维护源。

知识库与向量

管理文档内容、启用状态、检索效果和向量索引。

内容与检索
  1. 上传后先检查切片内容和归属范围，再决定是否启用；系统不会替你启用已停用知识。
  2. 项目价格、服务范围等结构化事实与知识文本冲突时，以项目中心的已发布数据为准。
  3. 修改知识内容后，按页面提示更新索引；“重建全部向量”只在全部成功后替换旧索引。
  4. 更换向量模型时，系统会先用新模型重建已有知识，成功后再切换；失败时继续使用旧模型和旧索引。
  5. 可用单条知识测试或 AI 调优中心检查召回、采用结果和最终回答。

AI 策略与调优

策略配置负责长期生效的规则，调优中心用于修改前后的验证。

先测试再发布
  1. AI 策略中的修改先成为草稿；点击“发布”后才作用于网页和企微真实对话。
  2. 数值项按页面显示的最小值、最大值和步进填写；问号提示解释数值增大或减小的影响。
  3. 首页文案和禁说词有独立维护页；禁说词修改后同样需要发布。
  4. AI 调优中心默认只模拟路由、检索和 Prompt，不写入真实会话、预约或坐席数据。
  5. 重要策略调整后运行回归用例，确认期望路由、回答要点、禁止内容和权威来源都通过。
  6. 转人工相关开关也在策略配置中：网页坐席工作台（默认封存）、人工粘性（humanHoldAfterHandoff）、转人工推送客户画像（profilePushEnabled，需自建应用 AgentId）、检索精排（Rerank，需通义 Key）。

账号、权限与数据范围

登录能力、功能权限和企微数据范围是三件不同的事。

最小权限
  • 客服账号（坐席）已封存：人工接待已迁移至企业微信原生接待，网页坐席工作台默认停用，坐席账号登录会被拒绝。如需临时恢复，可在 AI 策略配置开启“网页坐席工作台”。
  • 人工接待由企业微信接待成员承担：在企微管理后台把成员加入客服账号并配置接待规则；转人工时企微自动分配，接待成员在企微客户端直接回复客户。
  • 管理员按勾选的模块权限使用后台；超级管理员固定拥有全部权限。删除会话需要单独的“会话删除”权限，与查看权限分开授予。
  • 选择企业但不选客服号，表示可访问该企业下全部客服号；勾选具体客服号则只允许所选范围。
  • 客服、管理员和超级管理员的登录账号不能重复。

聊天模型与主备设置

不再固定绑定某一家平台；任何兼容 OpenAI Chat Completions 协议的模型都可以加入列表。

可自由切换
  1. 在模型平台官网注册、实名认证并开通 API 服务，然后创建 API Key。完整 Key 通常只展示一次，请立即妥善保存。
  2. 从平台文档找到 API Base URL 和 模型标识。Base URL 是接口根地址，例如 https://api.deepseek.com/v1，不要填写完整的 /chat/completions 路径。
  3. 进入“模型管理”，点击“添加新模型”，填写显示名称、Base URL、模型标识和 API Key。协议必须兼容 OpenAI；外部接口必须使用 HTTPS。
  4. 新增时可以直接选择“主模型”“备用模型”或“普通候选”。也可以保存后在列表中点击“设为主模型 / 设为备用”。
  5. 点击“综合测试”验证基础推理和质量评测能力。测试不会改变主备角色，也不会在失败后改用其他模型。
  6. 正常对话优先调用主模型；主模型报错、超时、限流或额度不足时，系统自动调用当前备用模型。质量评测页面也会显示当前主备模型的实际名称。
示例平台常用 Base URL模型标识示例
DeepSeekhttps://api.deepseek.com/v1deepseek-v4-flash（或 deepseek-v4-pro；deepseek-chat 已于 2026-07-24 停用）
智谱开放平台https://open.bigmodel.cn/api/paas/v4glm-4-flash（以控制台当日可用模型为准）
免费额度、免费模型、并发和限流规则会变化。备用模型也必须有可用 Key 和额度，否则主模型失败时无法兜底。
模型运行指标怎么看？

缓存命中表示复用了已缓存回答，通常可降低模型调用成本；熔断表示主模型连续失败后暂时由备用模型接管；模型调用占比、缓存趋势和运行计数从当前服务进程启动后累计，重启后重新计数。

腾讯云语音识别凭证

需要同时填写 SecretId 和 SecretKey。

语音转文字

  2. 进入“访问管理 CAM → API 密钥管理”。生产环境建议创建专用子账号，并只授予语音识别所需权限。

多企业微信客服接入

当前只支持“企业微信接管微信客服 → 开启 API → 企业内部开发”模式。

一企业一套凭证
  1. 在企业微信管理后台进入“应用管理 → 微信客服”，确认微信客服已由企业微信接管并开启 API。微信客服独立版（kf.weixin.qq.com）的凭证不能用于本系统。
  2. CorpID：企业微信管理后台“我的企业 → 企业信息”中获取。
  3. 接口调用应用 Secret：新接入应使用已加入“微信客服 → 可调用接口的应用”的自建应用 Secret，不能使用旧版微信客服系统应用 Secret 或未授权应用的 Secret。
  4. 回调 Token 与 EncodingAESKey：在配置微信客服接收消息服务器时设置，必须与本系统保存值完全一致。
  5. 先用三步向导创建并启用企业，再点击“从企微同步客服号”；新同步账号默认停用，检查业务范围和欢迎语后手动启用。
  6. 把系统生成的 /kf/callback/{企业编码} 专属地址填写到企业微信后台。
  7. 点击“一键检查接入状态”。“配置已通过”表示凭证和权限正常；向客服号发送测试消息并收到有效回调后才会显示“已连接”。
  8. open_kfid 优先通过自动同步获取；只有自动同步不可用时才建议手动添加。
  9. 配置接待成员（转人工的前提）：在企微管理后台该客服账号中添加接待成员并设置接待规则。客户转人工时，系统调用企微转接接口且不指定成员，由企微按接待规则自动分配；接待成员在企微客户端的“微信客服”应用中直接回复客户。
人工接待有粘性：转人工后 AI 不再插话，接待结束也不会自动恢复自动应答——只有接待成员在企微客户端把会话转回“智能助手”才会恢复（可用 agent.humanHoldAfterHandoff 关闭粘性）。转人工分配后，系统可把客户画像摘要推送给接待成员（agent.profilePushEnabled，需配置 wecom.appAgentId）。
不要再使用旧地址 /kf/callback。系统已统一为多企业模式，该地址不会接收回调。

常见问题

保存成功不等于第三方接口一定可用，可按下面顺序排查。

提示“密钥无效”或 401

检查是否复制了多余空格、是否把 Key 名称当成 Key 值、密钥是否被删除，以及开发和生产账号是否混用。

提示“额度不足”或限流

登录对应平台查看余额、免费额度、并发限制和账单。备用模型只有在自身也有可用额度时才能兜底。

企微回调验证失败

确认使用公网 HTTPS 地址，路径包含正确企业编码，并逐字核对 CorpID、Token 和 43 位 EncodingAESKey。

企微能回调但不能发送消息

重点检查是否误用了普通应用 Secret、客服号 open_kfid 是否属于当前企业、客服号是否启用，以及企微会话发送窗口限制。

腾讯地图地址解析失败

确认 Key 已开通 WebService API，安全限制包含实际服务器出口 IP，并检查地址是否包含城市和区县。

安全注意事项

接口密钥等同于账号密码，应按生产凭证管理。

必须遵守
  • 不要通过微信群、普通邮件或截图发送 Secret、Token、AESKey。
  • 开发环境和生产环境使用不同密钥，员工离职或疑似泄露后立即轮换。
  • 优先使用公司主体账号、专用子账号和最小权限，不使用个人账号长期承载生产服务。
  • 保存后后台不会回显密钥原文；需要更换时直接输入新值覆盖。
  • 不要把真实密钥写进 Git 仓库、部署文档、聊天记录或测试代码。
